# SayatSays для разработчиков

Как устроено приложение, как его запустить, проверить и выпустить новую версию, как сделать свою копию с напоминаниями.
Для пользователей — [README](../README.md).

Коротко: чистые HTML, CSS и ES-модули JavaScript **без сборщика** (никаких React, Vite, TypeScript). Сайт на GitHub Pages
из ветки `main`. Данные — только на устройстве, в IndexedDB. Service worker кэширует всё приложение, поэтому оно работает
офлайн. Расписание повторений — FSRS-6 через библиотеку [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs).

## Что где лежит

- `index.html`, `css/`, `js/`, `fonts/`, `icons/`, `manifest.webmanifest`, `sw.js` — само приложение
- `data/decks.json` — стартовые колоды (13 колод, 242 карточки); их получает каждый при первом запуске
- `data/progress-sm2.json` — прогресс Ромы из артефакта «Запомни», откуда всё выросло. Приложение его больше
  не загружает: у Ромы он уже в базе, а остальные начинают с нуля. Остался для истории и тестов
- `tests/` — проверки логики (запускаются в Node)
- `tools/`, `.github/workflows/reminder.yml` — отправка напоминаний (см. «Напоминания»)
- `CLAUDE.md` — контекст и правила проекта (его автоматически читает Claude Code), `ROADMAP.md` — задачи по порядку
- `icons/options/` — варианты иконки (выбран C «Петля»), `legacy/` — исходный артефакт

## Как устроен код

| Файл | Что делает |
|---|---|
| `js/app.js` | интерфейс: экраны, кнопки, настройки |
| `js/db.js` | хранилище на устройстве (IndexedDB) |
| `js/scheduler.js` | когда показывать карточку снова: обёртка над FSRS-6 (`vendor/ts-fsrs.mjs`) |
| `js/study.js` | занятие: какая карточка следующая, ответ, отмена ответа |
| `js/streak.js` | учебные дни (день начинается в 4:00) и серия с заморозками |
| `js/decks.js` | дерево колод, счётчики, очередь занятия, поля и проверка карточек, импорт колод |
| `js/claude.js` | колоды от Claude: инструкция для чата и разбор вставленного ответа |
| `js/stats.js` | статистика: ответы по дням, доля «знал», прогноз на 2 недели |
| `js/themes.js` | список тем оформления (сами цвета — в `css/app.css`) |
| `js/backup.js` | формат резервной копии |
| `js/migrate.js` | стартовые колоды при первом запуске и переход с SM-2 на FSRS |
| `js/push.js` | число на иконке и напоминания: разрешение, подписка на push |
| `js/config.js` | публичный ключ для push (приватный — только в GitHub Secrets) |
| `js/version.js` | номер версии (показывается внизу настроек) |
| `vendor/ts-fsrs.mjs` | библиотека FSRS (ts-fsrs 5.4.2, MIT), готовый файл из npm |
| `sw.js` | service worker: хранит приложение для работы офлайн, скачивает обновления, показывает напоминания |
| `tools/send-push.mjs` | отправляет push-напоминание; его запускает GitHub Actions |
| `tools/make-vapid.mjs` | создаёт ключи для push: приватный — сразу в GitHub Secrets, публичный — в `js/config.js` |

Правило проекта: логика отдельно от интерфейса. Расписание, серия, колоды, статистика, миграции — в модулях без DOM,
их проверяют тесты в Node. В `app.js` — только экраны и запись в базу.

## Запуск на компьютере

Двойной щелчок по `index.html` не сработает: по адресу `file://` браузер не загружает модули и JSON.
Нужен локальный сервер. В папке проекта:

```bash
python -m http.server 8000
```

Потом открой http://localhost:8000. (На Mac и Linux команда может называться `python3`.)

Service worker на localhost тоже работает, поэтому после правок может открыться старая версия из кэша.
Тогда подними версию (см. ниже) или в инструментах разработчика браузера: Application → Service workers → Unregister.

## Тесты

Нужен Node.js 20 или новее. Один раз установи пакеты, потом запускай проверки:

```bash
npm install
npm test
```

Пакет `fake-indexeddb` нужен только тестам: он имитирует IndexedDB в Node. `web-push` — скриптам напоминаний в `tools/`.
В само приложение ни один из них не попадает.

## Как выпустить новую версию

1. Подними номер на 1 в двух местах: `VERSION` в `sw.js` и в `js/version.js` (тест проверит, что они равны).
2. Если добавил новый файл приложения — допиши его в список `FILES` в `sw.js` (тест подскажет, какой забыт).
3. Смёрдж в `main` — через минуту-две GitHub Pages обновит сайт.
4. На телефоне при следующем открытии появится плашка «Доступно обновление» → «Обновить».
   Номер версии виден внизу настроек.

Если версию не поднять, телефон так и будет показывать старую версию из кэша.

## Как считается расписание

FSRS для каждой карточки помнит **стабильность** (через сколько дней вероятность вспомнить упадёт до 90 %)
и **сложность** (1–10). После ответа он пересчитывает их и назначает следующий показ так, чтобы карточка вспоминалась
с вероятностью, равной «целевой запоминаемости» из настроек (по умолчанию 90 %).

- Новая карточка: «Не знал» — снова через минуту, «Знал» — через 10 минут, потом — на дни.
- Забытая карточка: снова через 10 минут, потом — на дни. Не дольше года между повторениями.
- Под кнопками видно, когда карточка вернётся. «Выучено» — стабильность от 3 недель.
- Каждый ответ пишется в журнал (`reviewLog`): позже по нему можно подогнать параметры FSRS.
- Режим четырёх кнопок: «Не знал» = Again, «Трудно» = Hard, «Знал» = Good, «Легко» = Easy.

## Формат колод

Тот же, что в `data/decks.json`: `{ "decks": [колода, …] }`, колода — `{ id, name, type, parent, order, cards: [ … ] }`.

| type | что на карточке | поля карточки |
|---|---|---|
| `kz` | русский → казахский | `ru`, `kz`, `note` (необязательно) |
| `kzru` | казахский → русский | `kz`, `ru`, `note` (необязательно) |
| `en` | английское слово в предложении с пропуском | `word`, `ipa`, `ru`, `def`, `sentences[]` — слово в `{фигурных скобках}` |
| `qa` | вопрос и ответ | `q`, `a` |

`id` карточки необязателен: без него приложение сделает id по содержимому, и повторный импорт не задвоит карточки.
Проверка полей — `cardProblem` в `js/decks.js`, инструкция для Claude — `claudeInstructions` в `js/claude.js`.
Меняешь формат — поправь оба места.

## Колоды от Claude

Сам Claude в приложение ничего записать не может: данные лежат только на телефоне. Перенос идёт через буфер обмена:
«Добавить» → «Скопировать инструкцию для Claude» (формат + список колод пользователя с id) → ответ Claude →
«Вставить ответ Claude». Приложение находит JSON в ответе (в блоке кода или в тексте), проверяет каждую карточку
и показывает, что добавится. На экране колоды «От Claude» добавляет в инструкцию карточки этой колоды.

## Темы

Список — в `js/themes.js`, цвета — в `css/app.css`, в блоках `:root[data-theme="…"]`. Чтобы добавить тему, допиши её
в оба места. Тест `tests/themes.test.js` проверит, что у неё есть все переменные и текст хорошо читается (контраст по WCAG).
Тема ставится маленьким скриптом в `index.html` ещё до первой отрисовки (копия выбора — в `localStorage`).

## Напоминания

Утром и вечером на телефон приходит уведомление «12 карточек ждут повторения». Своего сервера нет: push отправляет
GitHub Actions по расписанию (`.github/workflows/reminder.yml`). В push нет ни текста, ни чисел — телефон сам считает
карточки по своей базе (`sw.js`), поэтому данные с телефона никуда не уходят. На GitHub лежит только подписка — адрес
телефона для push.

Поэтому напоминания приходят только на телефон, чья подписка лежит в секретах репозитория. У сайта
`dwlqx.github.io/SayatSays` это телефон Ромы. Остальным в настройках показывается «Число на иконке» (работает без GitHub),
а напоминания — свёрнутым пунктом для тех, у кого своя копия проекта.

### Своя копия проекта с напоминаниями

1. Сделай форк репозитория на GitHub (Fork).
2. В форке: Settings → Pages → Source: Deploy from a branch, ветка `main`, папка `/ (root)`.
   Через пару минут сайт будет на `https://<твой-логин>.github.io/SayatSays/`.
3. Actions → включи workflows (в форках они сначала выключены).
4. На компьютере склонируй форк, установи [GitHub CLI](https://cli.github.com) (`gh auth login`) и создай свои ключи:
   ```bash
   npm install
   node tools/make-vapid.mjs --force
   ```
   Приватный ключ скрипт сразу положит в секреты форка (`VAPID_PRIVATE_KEY`), публичный запишет в `js/config.js`.
   Там же поменяй `VAPID_SUBJECT` на адрес своего сайта (и ожидание в `tests/push.test.js`).
5. Закоммить `js/config.js`, подними версию (см. «Как выпустить новую версию»), запушь в `main`.
6. На телефоне открой свой сайт, установи на экран «Домой». Настройки → «Число на иконке» → «Напоминания по расписанию»
   → «Включить напоминания» → «Разрешить». Откроется «Подписка для GitHub» → «Скопировать».
7. На GitHub: Settings → Secrets and variables → Actions → New repository secret.
   Name: `PUSH_SUBSCRIPTION`, в Secret вставь скопированное → Add secret.
8. Проверь: Actions → «Напоминание» → Run workflow. Через минуту придёт уведомление.

Ссылки в приложении (на секреты и на эту инструкцию) сами ведут в репозиторий, с чьего сайта оно открыто.

### Как поменять время

В `.github/workflows/reminder.yml` строки `cron: 'минута час * * *'`. Время там **по UTC**: в Алматы UTC+5,
поэтому из времени Алматы вычитай 5 часов. Сейчас:

| Алматы | cron (UTC) |
|---|---|
| 7:09 | `'9 2 * * *'` |
| 18:45 | `'45 13 * * *'` |

Например, 8:30 по Алматы — `'30 3 * * *'`. Лишнее напоминание — удали его строку (и поправь тест в `tests/tools.test.js`).
GitHub запускает по расписанию с опозданием: обычно на несколько минут, иногда до часа. В начале часа очередь
больше всего, поэтому время лучше ставить не ровно в :00.

### Если что-то не так

- **Проверить без GitHub:** в приложении «Проверить уведомление» — придёт то же уведомление, что по расписанию.
- **Workflow красный** — открой запуск в Actions, там написано, что не так. GitHub пришлёт и письмо.
  - «Подписка устарела»: в приложении «Создать новую подписку» (или «Включить напоминания»), скопируй и обнови
    секрет `PUSH_SUBSCRIPTION` (Secrets → карандаш рядом с ним). Так бывает, если удалить приложение с экрана «Домой».
  - «Сервер push не принял подпись (403)»: ключи не совпадают — см. «Сменить ключи».
- **Расписание остановилось.** В публичном репозитории GitHub выключает расписание, если **60 дней** не было
  коммитов. Включить обратно: Actions → «Напоминание» → кнопка **Enable workflow**. Любой коммит тоже сбрасывает счёт.
- **Выключить напоминания:** Actions → «Напоминание» → «•••» → Disable workflow. Или выключи уведомления SayatSays
  в настройках телефона.
- **Сменить ключи** (если приватный ключ куда-то утёк): `node tools/make-vapid.mjs --force`, закоммить `js/config.js`,
  дождись обновления приложения на телефоне, потом «Создать новую подписку» и обнови `PUSH_SUBSCRIPTION`.

Логи Actions в публичном репозитории видны всем. Поэтому скрипт отправки никогда не печатает подписку и ключи.
Никаких секретов в коде и коммитах: приватный ключ и подписка — только в GitHub Secrets.
